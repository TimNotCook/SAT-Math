## 一、先说口径（可复现）

统计只算**会渲染给用户的文案**：

- `'...'` / `"..."` 字符串字面量（含中文才算）；
- `` `...` `` 模板字符串里 **`${}` 之外的文本片段**（模板是本项目 UI 文案的主要载体）；
- `.html` 的**文本节点**；`<script>`/`<style>` 内部按 JS 字面量算，不算文本节点；
- `//`、`/* */`、`<!-- -->` 注释一律不计。

复跑命令（脚本随仓库：`tools/copy_audit.py`）：

```bash
python3 tools/copy_audit.py --rev HEAD --summary exam.js exam.html bluebook-shell.js
python3 tools/copy_audit.py --rev HEAD --summary drill.js drill.html index.html
```

## 二、真实工作量：按像素数，不按源文件数

源文件那 113 条是**候选池**，不等于模考屏上的字——模考流程大量文案代码里已有 `OFFICIAL ?` 英文分支，线上显示本来就是 Bluebook 原词。

在线上模考页实跑（`getComputedStyle` 过滤不可见节点后取文本，2026-11-24 14:5x）：

- 模考**答题屏**可见中文：**2 项**（清空、完成）
- 模考**开场屏**可见中文：**10 项**（导航 5 + 题库胶囊 2 + 退出 + 清空 + 完成）
- 模考路径可达、需触发才现的中文：**4 条**（过期提示、格式校验 2 条、自动交卷、复制拦截、退出确认）
- 合计 **15 条**，逐条见 `docs/UI-COPY-TABLE.md`

| 方案 | 要动的地方 | 工作量 | 后果 |
|---|---|---|---|
| **A 全中文** | 把模考屏 13 个英文词回退成中文：Directions / Reference / Calculator / Mark for Review / Review / Submit / Back / Next / Hide / Start / Time Remaining / Section / Module / Question | **13 处回退** | 要推翻已就位的英文分支；界面全中文，与真实 Bluebook 差异大 |

**结论先摆正，两版都错**：上一版「全中文多翻 88 条」是假数（那 88 条练习层两案都不动）——老板第 3 条批得对，我认。但据此推「全中文更省」也不成立：按像素，**B 只要 9 条 + 2 处显隐，A 要 13 处回退**，B 更省。取哪个仍由老板定，理由应是保真与一致性，不是工作量。

## 三、分层规则（按「屏」，不按「例外」）

| 屏 | 语言 | 覆盖范围 |

| 模考流程：开考页 → 答题 → 题目导航 → 确认交卷 → Module 切换 | **100% 英文，Bluebook 原词** | 按钮、表头、弹窗、计时警告，**以及任何错误/过期提示**——模考屏上不出现一个中文字 |
