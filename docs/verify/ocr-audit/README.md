# 03/04 册"数字级"原页比对（2026-11-27）

## 为什么做这个

图已经逐条核到 213/243，答案全域结清；剩下没法核的 29 条全卡在"缺原页扫描"。
但 03 册（p102–141）、04 册（p140–177）我们**有整册扫描**，之前只做了"看图对图"，题干/选项文字没做过机器比对。
这一轮补上：把两册扫描 OCR 成文本，再用"库里每道题出现的数字都必须能在原页文本里找到"做自动核查。

## 工具

- `ocr.swift`：macOS Vision（`VNRecognizeTextRequest`，`.accurate`、不启用语言纠正、`en-US`）逐图 OCR，按行重建排版。
  编译：`swiftc -O ocr.swift -o ocr`。用法：`./ocr page.jpg [x0 y0 x1 y1]`（归一化裁剪框）。
- `ocr_columns.py`：先把一页扫描（一张图 = 左右两个书页）按竖向墨迹投影找出每页的栏间空隙，切成 4 栏再 OCR，
  避免两栏文字按同一行高度被合并、串行。输出 `/tmp/cols3/03-126-0.txt` 之类（`册-书页-栏`）。

## 比对方法

1. 取 `data/questions.js` 里 `R03-*`（123 题）、`R04-*`（159 题）共 **282** 题，文本 = 题干 + 选项 + 表格 spec（`TD_FIG_SPECS` 的 head/rows）。
2. 从库里文本抽取数字 token；只保留"3 位以上整数 / 带小数点 / 带斜杠"的（一两位纯整数满页都是，没有区分度）。
3. OCR 文本做归一：`−/–/—` 统一、去千分位逗号、去 `$` 与 `°`、`²`→`2`、去 `^{}`。
4. 库里每个 token 必须在该册 OCR 全文里出现（前后不能紧贴其它数字）。

## 结果

- 282 题里 **257 题全部命中，0 条真错**。
- 03 册 Topic 17（`SP2-*` 59 题，同属 03 册、扫描覆盖）再跑一遍：**58 题全命中**，唯一 flagged 是 `SP2-024` 的 `3/4`（竖排分数），**0 条真错**（`number-audit-sp2.json`）。
- 25 条 flagged（`number-audit-03-04.json`），逐条查完全部是 OCR 假阳性，分三类：
  - **竖排分数**（书上印成 分子在上、分母在下，OCR 读不出 `/`）：`R03-061`(3/4)、`R04-017`(1/3)、`R04-018`(92/47)、`R04-034`(7/76)、
    `R04-035`(8/3)、`R04-041`(1/20)、`R04-110`(√2/2)、`R04-117`(5/13)、`R04-119`(3/2)、`R04-120`(21/20)、`R04-122`(3/4)、
    `R04-123`(√3/3)、`R04-124`(50/7)、`R04-125`(24/51)、`R04-126`(3/5)、`R04-127`(20/21)、`R04-128`(1/12)、`R04-131`(1/4)、
    `R04-134`(11/12)、`R04-141`(199/2)、`R04-175`(2/5)、`R03-241`(1/9)、`R04-089`(121/3、11√130/3)。
    其中 `R04-018`（92/47）、`R04-034`（7/76）、`R04-089`（121/3、11√130/3）我另外把原页放大逐字看过，书上印的就是这些值，库无误。
  - **根号**：`R04-111` 库是 `1,089√3`，OCR 把 `√3` 的 3 粘成 `1,0893`，故匹配失败；原页放大确认无 1089 之外多余字符。
  - **栏裁边**：`R04-176`（p175 #36）库里 `3,856`，OCR 该栏裁到页边把 `3,8` 截断；把整页右半按原宽度重 OCR 得到完整
    "the perimeter of quadrilateral GMHN is 3,856 millimeters"，库无误。

## 这条核查覆盖到什么、没覆盖到什么

- 覆盖：题干/选项/表格里**所有数值**在 03、04 册原页上都真实存在（错一个数就会被抓出来）。
- 没覆盖：纯文字措辞逐字、单位/介词差异、OCR 认不出的符号。真正逐字核仍以人工读页为准（T18–T23 已逐题读完）。
- 价值：以后任何人改 03/04 册题目的数字，跑一遍这个脚本就能立刻知道改动是否越过了原书。
